# 1.4.7 全流程泄漏审计

## 结论

现行 46 特征模型（`sz_reflabel_clean`）**不存在标签/特征泄漏，也没有在推理阶段
使用参考格或参考种子**。陆地版最终分区 1,682 区、IoU 0.5822、综合 0.7424。

早期 47 特征版本曾把上限标签指示列 `label_zone_orig` 当成特征，OOF 0.9422、
最终 IoU 0.6019 属泄漏虚高，已废弃；本审计保留该记录并说明修正过程。

需要如实说明的口径边界：模型训练与评估都在深圳一个城市内，采用 2 km 散块
GroupKFold 的**城市内空间外推**，不是跨城市独立验证；后处理阈值是在深圳
实验中选定的全局常数。这些不是“逐格泄漏”，但属于泛化性限制。

## 1. 数据流与参考数据的位置

```
OSM PBF
  → 清理线网（去重/修断口/区域选类）
  → 原子面（polygonize）
  → 面块对 46 特征（面积/形状/边界类别/密度/周长等，全部来自 OSM）
  → XGB 合并概率 → 阈值 0.7 → 并查集 → 草稿
  → 陆地边界裁剪 + 栅格补缝 + 重叠消解 + 碎块吸收 + 清洞 + 简化
  → 最终分区
```

参考格 CSV 只出现在三处：

1. **离线标签**：每个原子面按“与参考格最大重叠”赋参考格 ID；面块对的标签
   为“两面是否属于同一参考格”。只在构建 `深圳-pairs-reflabel.pkl` 时使用。
2. **离线评估**：`tools/compare_iou.py` / `tools/similarity_report.py`
   读取参考 CSV，计算 IoU/匹配率/边界 F1/面积 KS/VI。
3. **出图对照**：对比图中把参考边界画成红线（发布版图已按陆地边界裁剪）。

推理链（`tools/infer_sz_clean.py`、`tools/train_sz_clean.py` 的推理分支、
收口脚本）不读取参考格的几何或 ID；栅格补缝、碎块吸收、清洞、简化均只使用
分区自身与陆地边界。陆地边界 `shenzhen-land-frame.geojson` 来自行政区边界+海岸线，
不来自参考格模板。

## 2. 特征审计

`commercial_zoning/models/sz_reflabel_clean/features.json` 共 46 个特征：

- 面积/形状：`a_area b_area area_ratio sum_area a_pp b_pp u_pp a_perim b_perim border_m`
- 边界类别比例：`bf_major bf_secondary bf_tertiary bf_local bf_weak bf_river
  bf_stream bf_water_poly bf_rail bf_natural bf_admin bf_landuse`
- 两侧类别长度：`a_* / b_*`（major/secondary/tertiary/local/weak/river/
  stream/water_poly/rail/natural/admin/landuse）

检查结果：

- 不含 `label`、`label_zone_orig`、参考格 ID、参考格面积/边界等任何由标准方案
  派生的列。
- 标签列在训练脚本的丢弃集合中：`{"i","j","label","label_zone_orig","city","tx","ty"}`。
- 面块对索引 `i/j`、瓦片坐标 `tx/ty` 不进入特征。

### 已修正的泄漏

47 特征版本包含 `label_zone_orig`：它标记两个面在“连续化上限标签”里是否同区，
与训练标签高度相关。修正前后：

| 版本 | 特征 | OOF AUC | OOF AP | 最终 IoU（参考框） |
|---|---|---|---|---|
| 泄漏版 | 47 | 0.9422 | — | 0.6019 |
| 修正版 | 46 | 0.7987 | 0.8902 | 0.5600（旧框）→ 0.5822（陆地版） |

OOF 下降 0.14、最终 IoU 下降约 0.04，符合“去掉强标签代理特征”的预期。

## 3. 训练/验证划分

- 以 2 km × 2 km 瓦片为组，共 708 个瓦片；同一瓦片的面块对只会出现在
  训练集或验证集之一（GroupKFold），避免相邻面块对跨折。
- 面块对共 39,987 行。
- 这是空间分块交叉验证，不是随机按行切分；OOF 0.7987 是同一城市内的
  空间外推成绩。

## 4. 阈值与后处理

- 合并概率阈值 0.7：在 OOF 上选取并固定，全城统一，不按格/按区调参。
- 草稿后的参数均为全局常数：碎块吸收 0.28 km²、面积上限 40 km²、
  简化 2 m、狭长比 8、栅格补缝 2 m。
- 这些常数由深圳的验证实验选定，属于“开发集调参”的常规范围；没有使用
  最终评估格逐区调参，也没有把参考格写入任何分区属性。

## 5. 为什么 0.5822 是可信的量级

1. **几何上限**：同一清理线网 + oracle 面合并的 IoU 上限约 0.6744；0.5822
   明显低于上限，不是“贴着标签拟合”的结果。
2. **参考边界可支撑度**：参考边界 15 m 内仅 67.35% 有 OSM 线；三分之一的
   参考边界在 OSM 中没有对应物，IoU 本身有结构性上限。
3. **面跨格**：41.9% 的原子面跨 ≥2 个参考格，涉及 70.6% 的面积；19.7% 的
   面在单一参考格内占比不足 90%，说明参考格与 OSM 面并非一一对应。
4. **无参考标签的独立对照**：只用 OSM 上限标签训练的 70j 模型（不接触标准
   方案标签）在同一陆地边界下得到 IoU 0.5704、匹配 0.9209、综合 0.7255，
   与标准标签模型 0.5822/0.8834/0.7424 同一量级。若 0.58 是靠泄漏，
   无参考标签的模型不应接近这个水平。
5. **泄漏版对比**：泄漏版 IoU 0.6019，比修正版高约 0.02–0.04，而不是高
   0.3；说明修正后的分数主要由几何/边界信息支撑。

## 6. 仍需披露的风险

- **城市内评估**：模型在深圳训练、在深圳评估；跨城市（广州/佛山/东莞等）
  泛化未验证。
- **参考标签参与训练**：标准方案是第三方成果，训练标签由其离线派生；
  评估不是“完全独立于参考体系”的盲测。
- **后处理常数**：在深圳实验中选定，换城市需重新验证。
- **参考 CSV 质量**：评估指标依赖该第三方数据的版本与精度。

## 7. 复现审计

```bash
python - <<'PY'
import json
f=json.load(open("commercial_zoning/models/sz_reflabel_clean/features.json"))
bad=[c for c in f if c in {"label","label_zone_orig"} or c.startswith("ref_")]
print(len(f), "leak columns:", bad)
PY
grep -n "label_zone_orig" tools/train_sz_clean.py
```

推理脚本中参考 CSV 仅用于末尾评估打印；删除该段不影响输出的分区几何。
