# 智域分区 · OSM 电信治理分区引擎

从 OpenStreetMap 矢量数据直接生成可解释、结构合理的电信治理分区。
线上推理只读 OSM；运营商标准微网格只在离线训练与评估时使用，不进入任何
推理特征，也不随仓库分发。

## 仓库内容

```text
commercial_zoning/      核心服务、结构收口、OSM 接入与预训练合并模型
vector_pipeline/        纯 OSM 矢量分区引擎（单文件 pipeline.py）
aoi_zoning_delivery/    自包含交付包：FastAPI + 单文件前端 + 模型 + 样例启动
examples/               命令行生成与离线对比图
tools/                  参考聚合统计、IoU 对比
figures/                离线对比图（参考网格图仅授权在私有仓发布）
data/china/             省级 PBF 放置目录（见 README）
requirements.txt        Python 依赖
```

## 环境

Python 3.10+，Windows / Linux / macOS。

```bash
python -m pip install -r requirements.txt
```

## 数据放置

把省级 OSM PBF 放到 `data/china/<province-id>-<日期>.osm.pbf`，
`province-id` 与 `commercial_zoning/china_provinces.json` 一致。
没有放置数据的省份会提示“目前无本地 OSM 数据，暂不支持”，不会联网下载。

## 快速开始（交付包）

```bash
cd aoi_zoning_delivery
python -m pip install -r requirements.txt
python run.py --port 8010
# 浏览器打开 http://127.0.0.1:8010/
```

前端地图使用本地 MapLibre bundle：默认在线底图是 Esri 浅灰，可选 Esri
影像 / Esri 街道 / OSM 瓦片；离线时勾选本地 OSM 多线路网底图
（水系/铁路/次干道/主干道）。左侧“数据图层”下拉可单独叠加 OSM 主干道、
全部道路、水系、铁路或标准方案（需自行放置参考 CSV）。生成、目录和分区
数据都来自本地 API。分区只画边界线，不填色；点击分区查看名称与属性。

前端流程：

1. 选择省 → 市/州 → 县/区；
2. 点“生成所选行政区”开始生成**整个所选行政区**；
3. 顶部显示阶段与百分比进度；县区结果有缓存时秒开；
4. 点击分区查看名称、面积、紧凑度、POI/建筑/路网密度、城市化、名称来源；
5. “清除缓存与结果”清空已生成缓存；刷新页面释放当前图层。

## 算法入口（一条线）

```text
OSM 行政单元选择
  → 只读取允许的 OSM 原始线
  → 面块（planar faces）
  → XGBoost 判“相邻面块是否同区”
  → 面积区间 / 形状 / 结构收口
```

### 初始切分线分层

| 层 | 使用的 OSM 线 | 说明 |
|---|---|---|
| tier1（主切分） | `waterway` river/canal；`admin_level` 6/8 边界 | 大骨架，先切开行政区与主要水系 |
| tier2（辅助） | motorway/trunk/primary/secondary/tertiary；铁路；barrier | 城市与乡镇的主次干道、铁路、围墙 |
| tier3（细切） | 建成区内的 local 道路；`waterway` stream | 只对已有建成区覆盖（landuse 缓冲）加密 |

初始切分不使用 `highway=path`、电力线、landuse/natural/water 多边形外边界
与海岸线。面块边界严格来自上述 OSM 线；<1000 m² 碎面并入共享边最长的
邻块，宽度 <20 m 的狭长面按窄区处理。

### XGBoost 合并模型

- 85 个可解释特征：共享边界的道路/水系等级与长度比例、面块面积/形状、
  POI/建筑/路网密度、行政层级、城市化分数等；不使用行政 ID 等记忆特征。
- 广东 10 个城市、29,401 对相邻面块训练；按城市分组的 test AUC **0.825**。
- 训练与推理统一使用 CPU `tree_method="hist"`。

### 面积区间收口（只要面积上下限）

线上不使用参考区数作为目标或上限，最终区数完全由面积区间与结构规则涌现。

每个行政单元的参考方案会给出核心城区/非核心城区/乡镇镇区/农村的
**面积占比**。收口时按城市化分数对面块排序，按这些面积占比落类，再套用
每档的面积上下限（参考方案 p10–p90）：

| 档位 | 面积下限 | 面积上限 |
|---|---:|---:|
| core（核心城区） | 0.52 km² | 2.44 km² |
| urban（非核心城区） | 0.77 km² | 3.94 km² |
| town（乡镇镇区） | 0.82 km² | 7.00 km² |
| rural（农村） | 3.44 km² | 41.2 km² |
| remote（稀疏山区） | 10 km² | 250 km² |

面积占比与上下限都是参考方案的**聚合统计**，不包含参考几何、区名或区号。

结构收口按固定顺序执行：

1. 重叠修复；有内环的区与其内部区合并后按原区数重切，消除“区中区”；
2. 平行长条簇整体合并为更大的 OSM 边界区；
3. 空内环（闭环道路圈）填实；
4. 落类前先切开超过最大档上限的超大面块，避免单块跨越面积阈值把整个类
   面积带偏；
5. 欠面积区并入共享边最长的同档邻区；只有 <0.6 km² 的跨档碎块允许并入
   邻区，防止城镇/城区类吞并农村面积；
6. 超面积区沿内部 OSM 线切分；没有 OSM 线可依时按主轴递归二分，得到
   紧凑近方块，**不生成全局方格网**；
7. 收口后再次修复重叠，最后只做超面积切分（不再合并），避免重新制造
   内环；<0.05 km² 的孤立残片删除。

### 市/省 = 县区之和

- 广东 124 个县区 + 2 个直管市（东莞、中山）逐个生成；
- 一个市的最终分区 = 该市所有县区结果之和；
- 全省 = 所有市之和；
- 县区结果缓存命中时前端秒开，不重复计算。

## 命令行生成

```bash
python examples/generate_example.py \
  --bbox 113.98602,22.50064,114.10027,22.5898 \
  --name 福田区 --level 6 \
  --scope county --center 114.04559,22.54516 \
  --out out/futian.geojson
```

脚本调用 `commercial_zoning.region_service.generate_region`，与线上 API 同一条路径。

## 与标准方案的对比图

`examples/compare_city_crops.py` 读取用户提供的标准微网格 CSV，生成三联图
（本引擎 | 标准方案 | 叠加）以及 4×4 km 局部图；灰色细线为 OSM 道路/水系，
可直接检查边界是否贴线。标准微网格只用于离线对比，不参与推理。

```bash
python examples/compare_city_crops.py --reference /path/to/reference.csv \
  --city "中山=out/中山市.geojson=cache/<key>/lines.geojson" \
  --out-dir figures/cities_area
```

## 参考聚合统计与 IoU

`commercial_zoning/reference_targets.json` 保存参考微网格的**聚合统计**：
每个市/县区的分区数量、面积分位数、覆盖面积、行政中心点与
core/urban/town/rural 面积占比，不含任何参考几何、名称或编码。它由
`tools/build_reference_targets.py` 离线生成。

没有标准微网格的省份不使用任何参考区数，而是按 **OSM 路网密度分级**决定
面积预算。`commercial_zoning/area_budget.json` 由参考方案离线统计得到
（只有聚合量）：

| 场景（密度级） | 面积 p10/p50/p90 km² | 均值 km² |
|---|---|---:|
| 核心城区 | 0.52 / 1.00 / 2.44 | 1.38 |
| 非核心城区 | 0.77 / 1.74 / 3.94 | 2.21 |
| 乡镇镇区 | 0.82 / 2.44 / 7.00 | 3.45 |
| 农村 | 3.44 / 16.64 / 41.2 | 20.92 |

`commercial_zoning/land_mask_guangdong.geojson` 是粗化的广东陆地轮廓，
只用于把含海域的沿海行政面裁到陆地；不含微网格结构。

`tools/compare_iou.py` 用稀疏重叠对计算省/市级 IoU（参考最佳匹配、
贪心 1-1、全参考 IoU），可直接跑省、市或任意 bbox：

```bash
python tools/compare_iou.py --ours out/guangdong.geojson \
  --reference /path/to/reference.csv --city 广州 --out iou_gz.json
```

## 已知限制

- 纯 OSM 无法逐线复刻人工微网格（参考方案约 40% 边界在 OSM 中不可见），
  全参考 IoU 约 0.21–0.40；本引擎优先保证结构合理与边界可解释。
- 乡村/山地 OSM 线稀疏，面积较大的区只能做紧凑近方块补齐。
- 沿海行政多边形可能包含海域矩形，生成时按陆地掩膜裁剪。
- 大县精细路径较慢，建议后台预生成；缓存命中为毫秒级。

## 不包含的内容

- 运营商参考微网格数据（不随仓库分发）。
- 省级/城市 PBF（体积大，请按 `data/china/README.md` 自行放置）。
- 运行缓存、日志与训练中间产物。
