# 智域分区 · OSM 电信治理分区引擎

从 OpenStreetMap 矢量数据直接生成可解释、带名称的电信治理分区。
线上推理只读 OSM 矢量数据；运营商标准微网格不随仓库分发，也不进入推理特征。

## 仓库内容

```text
commercial_zoning/      核心服务、质量清理、OSM 数据接入与预训练合并模型
vector_pipeline/        纯 OSM 矢量分区引擎（单文件 pipeline.py）
aoi_zoning_delivery/    自包含交付包：FastAPI + 单文件前端 + 模型 + 样例启动
examples/               命令行生成示例
data/china/             省级 PBF 放置目录（见 README）
requirements.txt        Python 依赖
```

## 环境

- Python 3.10+
- Windows / Linux / macOS

```bash
python -m pip install -r requirements.txt
```

## 数据放置

把省级 OSM PBF 放到 `data/china/<province-id>-<日期>.osm.pbf`，
`province-id` 与 `commercial_zoning/china_provinces.json` 一致。
没有放置数据的省份会提示“目前无本地 OSM 数据，暂不支持”，不会联网下载。

## 快速开始（交付包）

```bash
cd aoi_zoning_delivery
python -m pip install -r requirements.txt
python run.py --port 8010
# 浏览器打开 http://127.0.0.1:8010/
```

前端地图使用本地 MapLibre bundle：默认在线底图是 Esri 浅灰（v1.7.0 风格），
可选 Esri 影像 / Esri 街道 / OSM 瓦片；离线时勾选本地 OSM 多线路网底图
（水系/铁路/次干道/主干道）。左侧“数据图层”下拉可单独叠加 OSM 主干道、
全部道路、水系、铁路或广东移动标准方案。生成、目录和分区数据都来自本地 API。
分区只画边界线（白色描边 + 深色主线），不填色；点击分区查看名称与属性。
城市/县区可勾选“快速预览”（行政单元 + 主干道，约 1–5 分钟）；不勾选则走
完整精细管线（大市可能 30–60 分钟）。

前端流程：

1. 选择省 → 市/州 → 县/区；
2. 点“生成所选行政区”开始生成**整个所选行政区**（不是经纬度小方块）；
3. 顶部显示阶段与百分比进度，结果落盘缓存；
4. 点击分区查看名称、面积、紧凑度、POI/建筑/路网密度、城市化、名称来源；
5. 勾选“标准微网格边界”可在同一张图上叠加参考微网格边界（只画线）；
6. “清除缓存与结果”清空已生成缓存；刷新页面释放当前图层。

广东省的分区数量与面积目标来自 `commercial_zoning/reference_targets.json`
（由参考微网格统计出的聚合指标，不含参考几何）：市 = 下辖县区目标之和，
省 = 所有市目标之和。首次生成市/省会逐县区精细分区并缓存，耗时较长，
但每次只处理一个县区，内存占用有界；之后重复打开直接命中缓存。
参考 CSV 不随仓库分发，需自行放到 `data/reference/` 才能显示标准边界。

## 命令行生成

```bash
python examples/generate_example.py \
  --bbox 113.98602,22.50064,114.10027,22.5898 \
  --name 福田区 --level 6 \
  --scope county --center 114.04559,22.54516 \
  --out out/futian.geojson
```

脚本调用 `commercial_zoning.region_service.generate_region`，与线上 API 同一条路径。

## 算法要点

```text
OSM PBF
  → 原始道路/铁路/水系/行政界/土地用途/自然/公园校园/海岸线切分
    （不合并双线、不做同名 stroke、不平滑，边界严格落在 OSM 线上）
  → 初始面块；<1000 m² 碎面并入共享边最长的邻块，<20 m 狭长面按窄区处理
  → 预训练 XGBoost 判“相邻块是否同区”（CPU hist）
  → 局部目标面积合并 + 主干道否决 + 形状约束
  → 窄区/低 pp/长条/凹形清理；<180 m 细长条按邻近区 Voronoi 分段重分配
  → 平行长条簇整体合并为更大的 OSM 边界块（不做非 OSM 网格切分）
  → 20 m+80 m 两级触手修剪
  → 飞地/洞/碎块清理 + 单部件，覆盖保持、重叠修复、缝隙封口
  → OSM 地名/社区/地块投票命名，重名加方位后缀
```

关键约束：

- 线上只读 OSM；标准微网格不进入任何推理特征。
- 有 OSM 线的地方必须贴线；没有线的地方切成近方块，不做层叠长条。
- 双线快速路/江岸之间的 100–150 m 无路细条由邻近区吸收，不保留为独立长条。
- 并排的多个长条会让位于一个更大的 OSM 边界块：面积/计数允许 ±12%，
  各类面积可在 0.55–1.8 倍类均值之间浮动，优先贴 OSM 线而不是硬凑数量。
- 每个区单连通、无洞（大飞地除外）、无 <0.15 km² 碎块；重叠 0，覆盖率 100%。
- XGBoost 训练/推理使用 CPU hist（`tree_method="hist"`）。

## 参考目标与 IoU

`commercial_zoning/reference_targets.json` 保存参考微网格的**聚合统计**：
每个市/县区的分区数量、面积分位数、覆盖面积和行政中心点，不含任何
参考几何、名称或编码。它由 `tools/build_reference_targets.py` 离线生成。
推理时用它设定目标区数、面积阈值和初始候选块大小。

没有标准微网格的省份不使用任何参考区数，而是按 **OSM 路网密度分级**决定
面积预算。`commercial_zoning/area_budget.json` 由
`tools/build_area_budget.py` 从参考方案离线统计得到（只有聚合量，不含几何、
名称或编码）：

| 场景（密度级） | 路网密度 km/km²（p10–p90） | 面积 p10/p50/p90 km² | 均值 km² |
|---|---|---|---:|
| 核心城区 | 5.2–22.0 | 0.52 / 1.00 / 2.44 | 1.39 |
| 非核心城区 | 3.0–12.5 | 0.77 / 1.74 / 3.94 | 2.21 |
| 乡镇镇区 | 2.2–10.1 | 0.83 / 2.45 / 7.01 | 3.46 |
| 农村 | 0.30–4.37 | 3.44 / 16.66 / 41.2 | 20.96 |
| 沙漠/高原等稀疏区 | < 0.15 | 按密度外推 | 40–100 |

推理时把行政区切成约 1.5 km 的粗网格，按每格的路网密度分到上表某一级，
目标区数 = Σ（该级面积 ÷ 该级平均面积）。因此建成区分得细、农村分得粗，
沙漠高原允许很大的区，不会用一个固定面积套全国。分级阈值和面积统计都在
`area_budget.json` 里，代码中不写死任何参考计数；广东的市/县区数只来自
`reference_targets.json`。分区完成后按目标区数收口：多则优先合并低密度的
农村区（保留城区细粒度），少则沿 OSM 线切分；超过参考 p90 的超大区先切分，
有 OSM 线沿线路切，无线地区切近方块。

`commercial_zoning/land_mask_guangdong.geojson` 是粗化的广东陆地轮廓，
只用于把含海域的沿海行政面裁到陆地；不含微网格结构。

`tools/compare_iou.py` 用稀疏重叠对计算省/市级 IoU（参考最佳匹配、
贪心 1-1、全参考 IoU），可直接跑省、市或任意 bbox：

```bash
python tools/compare_iou.py --ours out/guangdong.geojson \
  --reference /path/to/reference.csv --city 广州 --out iou_gz.json
```

## 已知限制

- 纯 OSM 无法逐线复刻人工微网格：标准方案约 40% 边界来自 OSM 不可见的
  社区/单位界，全参考 IoU 约 0.31–0.33。
- 地级市/全省首次生成会逐城市跑精细分区并缓存，耗时较长；之后命中缓存。
- 沿海行政区的 OSM 行政面可能含海域，已用陆地轮廓裁剪大块海域，
  细小岛屿/岸线仍可能有少量误差。
- 首次读取省级 PBF/生成较慢，缓存命中后为毫秒级。

## 不包含的内容

- 运营商参考微网格数据（不随仓库分发）。
- 省级/城市 PBF（体积大，请按 `data/china/README.md` 自行放置）。
- 运行缓存、日志与训练中间产物。
