# 智域分区 · OSM 电信治理分区引擎

从 OpenStreetMap 矢量数据直接生成可解释、结构合理的电信治理分区。
线上推理只读 OSM；运营商标准微网格只在离线训练与评估时使用，不进入任何
推理特征，也不随仓库分发。

## 仓库内容

```text
commercial_zoning/      核心服务、结构收口、OSM 接入与预训练合并模型
vector_pipeline/        纯 OSM 矢量分区引擎（单文件 pipeline.py）
aoi_zoning_delivery/    自包含交付包：FastAPI + 单文件前端 + 模型 + 样例启动
examples/               命令行生成与离线对比图
tools/                  参考聚合统计、IoU 对比
figures/                离线对比图（参考网格图仅授权在私有仓发布）
data/china/             省级 PBF 放置目录（见 README）
requirements.txt        Python 依赖
```

## 环境

Python 3.10+，Windows / Linux / macOS。

```bash
python -m pip install -r requirements.txt
```

## 数据放置

把省级 OSM PBF 放到 `data/china/<province-id>-<日期>.osm.pbf`，
`province-id` 与 `commercial_zoning/china_provinces.json` 一致。
没有放置数据的省份会提示“目前无本地 OSM 数据，暂不支持”，不会联网下载。

## 快速开始（交付包）

```bash
cd aoi_zoning_delivery
python -m pip install -r requirements.txt
python run.py --port 8010
# 浏览器打开 http://127.0.0.1:8010/
```

前端地图使用本地 MapLibre bundle：默认在线底图是 Esri 浅灰，可选 Esri
影像 / Esri 街道 / OSM 瓦片；离线时勾选本地 OSM 多线路网底图
（水系/铁路/次干道/主干道）。左侧“数据图层”下拉可单独叠加 OSM 主干道、
全部道路、水系、铁路或标准方案（需自行放置参考 CSV）。生成、目录和分区
数据都来自本地 API。分区只画边界线，不填色；点击分区查看名称与属性。

前端流程：

1. 选择省 → 市/州 → 县/区；
2. 点“生成所选行政区”开始生成**整个所选行政区**；
3. 顶部显示阶段与百分比进度；县区结果有缓存时秒开；
4. 点击分区查看名称、面积、紧凑度、POI/建筑/路网密度、城市化、名称来源；
5. “清除缓存与结果”清空已生成缓存；刷新页面释放当前图层。

## 算法入口（一条线）

```text
OSM 行政单元选择
  → 只读取允许的 OSM 原始线
  → 面块（planar faces）
  → XGBoost 判“相邻面块是否同区”
  → 面积区间 / 形状 / 结构收口
```

### 初始切分线：由标准方案反推

先用标准微网格的边界反推它实际贴在哪些 OSM 特征上（方法、全省表和城市
个案见 `docs/REFERENCE_BOUNDARY_ANALYSIS.md`）：

| 场景 | 边界点 10 m 内可解释 | 主要命中特征（10 m 内占比） |
|---|---:|---|
| 城建区 | 60.5% | 主干道 38.9%、水面边界 17.1%、三级路 13.5%、本地路 9.7%、河流 5.1%、铁路 3.3%、路径 3.2%、自然植被 2.6% |
| 乡镇区 | 33.5% | 主干道 34.9%、水面边界 18.6%、三级路 12.8%、本地路 11.4%、河流 8.8%、自然植被 3.1%、小溪 2.9%、铁路 2.4% |
| 乡村/自然区 | 12.3% | 主干道 26.9%、水面边界 25.8%、河流 11.5%、自然植被 10.2%、本地路 9.0%、三级路 7.3%、铁路 2.3% |

据此只用标准方案实际使用的特征线：

| 特征线 | 用法 |
|---|---|
| 主干道/次级干道（motorway/trunk/primary/secondary） | 全部 |
| 三级路（tertiary） | 全部 |
| 本地路（residential/unclassified/living_street） | 建成区内全部；建成区外仅长度 ≥600 m |
| 服务路 + 步行/小径 | 仅建成区内（弱信号，约占标准边界 1–3%） |
| 铁路 | 全部（弱） |
| 河流/运河、小溪/排水沟 | 河流全部；小溪长度 ≥200 m |
| 水面多边形边界 | 面积 ≥0.5 ha（标准方案在乡村边界中占约 26%） |
| 自然植被边界（wood/scrub/grassland/wetland） | 面积 ≥5 ha（北部山区占约 19%） |

不使用：行政区边界（level 4–10，标准方案内部边界几乎不贴）、landuse/
公园/公共设施/建筑边界（合计 <2%）、围栏/墙/路缘（<0.15%）、电力线、
海岸线。双线道路先按 ref/name 合并中心线，再做几何平行合并，保证
“一条路一条边界”。

初始块完全由这些线决定，**不再按目标区数/目标面积补切**。中山的初始块
在选线校准时为 1,459 个（参考 538 区的 2.71 倍），道路网清洗后为 1,323
个（2.46 倍），均落在 1.5–3 倍区间；水面面块在 XGB 前并入邻区，
<0.02 km² 的封闭微环并入宿主，避免后续区中区。

### 道路预处理：一路一线

在抽线阶段（初始切分、XGB 训练、推理之前）先清洗道路网：

- 同名/同 ref 的连续 OSM way 先合并为整条路；
- 近平行、方向一致或相反、重叠 ≥80%、最小间距 9–22 m 的线做聚类
  （同名/同 ref 放宽，不同 ref 不合并，不同等级仅在 <9 m 时视为重复）；
  每个簇只保留一条线；方向相反的双线取中心线；
- 小闭环（封闭面积 ≤0.02 km² 的环岛/环路碎片）直接删除；
- 道路两侧的服务路/人行道/水岸/自然边界等侧线，若 ≥70% 落在 25 m
  道路缓冲带内且与道路平行，删除；道路因此是一条**无面积中线**，路口
  是**无面积十字**，不再留出空的道路带/道路方块。
- 中山实测（2.4.1 同 bbox）：53,079 条道路 → 46,938 条（合并平行
  3,034、删除环岛 589），再删除道路走廊侧线 833 条，输出 53,357 条线；
  初始块 1,323（参考 2.46 倍）。训练窗口同样先做这套清洗再构造 pair，
  规则与推理完全一致。

### XGBoost 合并模型

- 87 个特征：共享边界的道路/水系/水面/小溪等级比例、块面积/形状、
  POI/建筑/路网密度、行政层级、城市化分数等；不使用行政 ID 等记忆特征。
- 10 个城市、3,599 对相邻块（清洗后的线网）；按城市分组的 5 折交叉验证 AUC **0.969**。
- 训练与推理统一使用 CPU `tree_method="hist"`。

### 概率驱动合并与结构收口

- 不使用参考区数或每档面积作为目标/上限；按 XGB 概率从高到低合并相邻
  块，只保留结构约束：单连通、不新增洞、紧凑度/长宽比、最大面积上限。
- 收口不再做“目标区数/目标面积”切分，也不做规则网格或紧凑补切；只做
  内环消除、多部件拆分、<0.05 km² 碎片删除、重叠修复。
- 因此最终区数由 XGB 概率与结构约束自然涌现，而不是从参考统计硬凑。

### 市/省 = 县区之和

- 广东 124 个县区 + 2 个直管市（东莞、中山）逐个生成；
- 一个市的最终分区 = 该市所有县区结果之和；
- 全省 = 所有市之和；
- 县区结果缓存命中时前端秒开，不重复计算。

## 结果（中山市，2.4.1）

| 指标 | 本引擎 | 参考方案 |
|---|---:|---:|
| 初始块（XGB 前） | 1,323（2.46x） | — |
| 最终区数 | 523 | 538 |
| 面积 p10 / p50 / p90（km²） | 0.22 / 3.58 / 7.08 | 0.80 / 1.88 / 7.29 |
| 内环 / 多部件 | 0 / 0 | — |
| 长宽比 >5 / >4 / 最大 | 1 / 6 / 5.75 | — |
| 贪心 1-1 IoU | 0.3163 | — |
| 全参考 IoU | 0.1781 | — |
| 1-1 匹配覆盖率 | 56.3% | — |

区数接近参考（-2.8%），城建区小块明显增多：密集城区 4×4 km 窗口本
引擎 15–16 区（参考窗口 2–8 区），乡村保持大块。为消除狭长，收口先对
合并后长宽比仍 >3 的区沿内部 OSM 线切分，无线时沿长轴切紧凑块；最后把
仍 >5 或宽度 <20 m 的薄区并入邻区。区域属性卡按最终区与初始块面积加权
重算，密度字段取到的是邻域加权值而不是单个块值。

道路网清洗在本版先于分区、打标签和训练执行（见上节）：一路一线、双线
合并中心线、环岛删除、道路走廊侧线删除，道路与路口为零面积中线/十字。
XGB 也在清洗后的线网上重训（3,599 对，分组 CV AUC 0.969），推理与训练
口径一致。

对比图：`figures/cities_ref/中山_full.png`、`中山_crop1.png`、
`中山_crop2.png`（左：本引擎；中：参考；右：叠加，含 OSM 线）；
IoU 见 `figures/cities_ref/iou_中山_2.4.1.json`。

此前的 1.4.3（484 区、p50 2.06、贪心 IoU 0.345）与 2.3.6（551 区、
长宽比 >5 为 0）分别保留在 `figures/cities_area/` 和 2.3.x 缓存中供
对照；2.4.x 的主变化是道路与道路走廊预处理，以及用清洗后线网重训
XGB。

  --bbox 113.98602,22.50064,114.10027,22.5898 \
  --name 福田区 --level 6 \

## 与标准方案的对比图

`examples/compare_city_crops.py` 读取用户提供的标准微网格 CSV，生成三联图
（本引擎 | 标准方案 | 叠加）以及 4×4 km 局部图；灰色细线为 OSM 道路/水系，
可直接检查边界是否贴线。标准微网格只用于离线对比，不参与推理。

```bash
python examples/compare_city_crops.py --reference /path/to/reference.csv \
  --city "中山=out/中山市.geojson=cache/<key>/lines.geojson" \
  --out-dir figures/cities_ref
```

## 参考聚合统计与 IoU

`commercial_zoning/reference_targets.json` 保存参考微网格的**聚合统计**：
每个市/县区的分区数量、面积分位数、覆盖面积、行政中心点与
core/urban/town/rural 面积占比，不含任何参考几何、名称或编码。它由
`tools/build_reference_targets.py` 离线生成。

参考统计**不进入线上最终收口**：区数/面积不再作为目标或上限；它只用于
离线选特征线、评估 IoU 和生成对比图。`commercial_zoning/area_budget.json`
保留为路网密度上下文（供 XGB 特征与初始候选规模参考），其中面积区间也
不再作为硬约束：

| 场景（密度级） | 面积 p10/p50/p90 km² | 均值 km² |
|---|---|---:|
| 核心城区 | 0.52 / 1.00 / 2.44 | 1.38 |
| 非核心城区 | 0.77 / 1.74 / 3.94 | 2.21 |
| 乡镇镇区 | 0.82 / 2.44 / 7.00 | 3.45 |
| 农村 | 3.44 / 16.64 / 41.2 | 20.92 |

`commercial_zoning/land_mask_guangdong.geojson` 是粗化的广东陆地轮廓，
只用于把含海域的沿海行政面裁到陆地；不含微网格结构。

`tools/compare_iou.py` 用稀疏重叠对计算省/市级 IoU（参考最佳匹配、
贪心 1-1、全参考 IoU），可直接跑省、市或任意 bbox：

```bash
python tools/compare_iou.py --ours out/guangdong.geojson \
  --reference /path/to/reference.csv --city 广州 --out iou_gz.json
```

## 已知限制

- 纯 OSM 无法逐线复刻人工微网格（参考方案约 40% 边界在 OSM 中不可见）；
  放宽区数/面积并强制零区中区后，全参考 IoU 约为 0.15–0.35，结构合理性
  优先于 IoU。
- 乡村/山地 OSM 线稀疏，允许保留较大的区；不再用人工方格/紧凑补切。
- 沿海行政多边形可能包含海域矩形，生成时按陆地掩膜裁剪。
- 大县精细路径较慢，建议后台预生成；缓存命中为毫秒级。

## 不包含的内容

- 运营商参考微网格数据（不随仓库分发）。
- 省级/城市 PBF（体积大，请按 `data/china/README.md` 自行放置）。
- 运行缓存、日志与训练中间产物。
