# 智域分区 · OSM 电信治理分区引擎

从 OpenStreetMap 矢量数据直接生成可解释、带名称的电信治理分区。
线上推理只读 OSM 矢量数据；运营商标准微网格不随仓库分发，也不进入推理特征。

## 仓库内容

```text
commercial_zoning/      核心服务、质量清理、OSM 数据接入与预训练合并模型
vector_pipeline/        纯 OSM 矢量分区引擎（单文件 pipeline.py）
aoi_zoning_delivery/    自包含交付包：FastAPI + 单文件前端 + 模型 + 样例启动
examples/               命令行生成示例
data/china/             省级 PBF 放置目录（见 README）
requirements.txt        Python 依赖
```

## 环境

- Python 3.10+
- Windows / Linux / macOS

```bash
python -m pip install -r requirements.txt
```

## 数据放置

把省级 OSM PBF 放到 `data/china/<province-id>-<日期>.osm.pbf`，
`province-id` 与 `commercial_zoning/china_provinces.json` 一致。
没有放置数据的省份会提示“目前无本地 OSM 数据，暂不支持”，不会联网下载。

## 快速开始（交付包）

```bash
cd aoi_zoning_delivery
python -m pip install -r requirements.txt
python run.py --port 8010
# 浏览器打开 http://127.0.0.1:8010/
```

前端地图使用本地 MapLibre bundle 和纯背景图层，不请求任何外部底图、
字体或瓦片服务；生成、目录和分区数据都来自本地 API。

前端流程：

1. 选择省 → 市/州 → 县/区；
2. 点“生成所选行政区”开始生成；
3. 顶部显示阶段与百分比进度，结果落盘缓存；
4. 点击分区查看名称、面积、紧凑度、POI/建筑/路网密度、城市化、名称来源；
5. “清除缓存与结果”清空已生成缓存；刷新页面释放当前图层。

县/区生成整县；市默认生成约 12×11 km 核心区；省为行政区引擎概览。

## 命令行生成

```bash
python examples/generate_example.py \
  --bbox 113.98602,22.50064,114.10027,22.5898 \
  --name 福田区 --level 6 \
  --scope county --center 114.04559,22.54516 \
  --out out/futian.geojson
```

脚本调用 `commercial_zoning.region_service.generate_region`，与线上 API 同一条路径。

## 算法要点

```text
OSM PBF
  → 原始道路/铁路/水系/行政界/土地用途/自然/公园校园/海岸线切分
    （不合并双线、不做同名 stroke、不平滑，边界严格落在 OSM 线上）
  → 初始面块；<1000 m² 碎面并入共享边最长的邻块，<20 m 狭长面按窄区处理
  → 预训练 XGBoost 判“相邻块是否同区”（CPU hist）
  → 局部目标面积合并 + 主干道否决 + 形状约束
  → 窄区/低 pp/长条/凹形清理；<180 m 细长条按邻近区 Voronoi 分段重分配
  → 平行长条先并后切近方块；20 m+80 m 两级触手修剪
  → 飞地/洞/碎块清理 + 单部件，覆盖保持、重叠修复、缝隙封口
  → OSM 地名/社区/地块投票命名，重名加方位后缀
```

关键约束：

- 线上只读 OSM；标准微网格不进入任何推理特征。
- 有 OSM 线的地方必须贴线；没有线的地方切成近方块，不做层叠长条。
- 双线快速路/江岸之间的 100–150 m 无路细条由邻近区吸收，不保留为独立长条。
- 每个区单连通、无洞（大飞地除外）、无 <0.15 km² 碎块；重叠 0，覆盖率 100%。
- XGBoost 训练/推理使用 CPU hist（`tree_method="hist"`）。

## 与标准方案的对比图

`examples/compare_reference_maps.py` 读取用户提供的标准微网格 CSV，为广州、
深圳、佛山、东莞、珠海、汕头和全省生成三联图（本引擎 | 标准方案 | 边界叠加），
结果见 `figures/reference_compare/index.md`。标准微网格只用于离线对比，
不参与推理；沿海城市结果已裁剪到标准网格覆盖范围。

城市图使用产品默认的 **12×11 km 核心区 + 精细路网分区**，与标准微网格
同一尺度；加 `--city-mode whole` 可改为全市行政区引擎对比（基本单元是
乡镇/街道，区数会明显少于微网格）。省图为行政区引擎概览。

## 已知限制

- 纯 OSM 无法逐线复刻人工微网格：标准方案约 40% 边界来自 OSM 不可见的
  社区/单位界，全参考 IoU 约 0.31–0.33。
- 大县（>1,500 km²）精细路径较慢，当前以行政区引擎或粗粒度精细兜底。
- 沿海行政区的 OSM 行政面可能含海域，尚未全部扣除。
- 首次读取省级 PBF/生成较慢，缓存命中后为毫秒级。

## 不包含的内容

- 运营商参考微网格数据（不随仓库分发）。
- 省级/城市 PBF（体积大，请按 `data/china/README.md` 自行放置）。
- 运行缓存、日志与训练中间产物。
