## 1. 数据阶段：参考边界有多少不在 OSM 上

参考方案 1707 个微网格，面积 2438 km²；清洗后的 OSM 线 187,637 条
（soft 153,636、major 13,033、stream 6,621、rail 5,586、water_poly
3,890、river 1,345）。

- 参考边界 36.2 万个采样点：**54.1% 在 OSM 线 15 m 内，64.8% 在 25 m 内**，
  中位距离 12.7 m。
- 距离 >15 m 的“缺失边界”占 **45.95%**，共 12,382 段：
  段长 p50 150 m、p90 725 m、均值 329 m；弦/长度 p50 1.38（不是纯直线）。
- 缺失段两端：**54.1% 两端都在 OSM 附近，35.4% 只有一端**。
- 核心区缺失比例 42.3%，乡镇/农村更高（约 50%）。
- 缺失段附近可解释特征很弱：建筑 ≤10 m 仅 2.9%，landuse ≤25 m 41.1%，
  admin L8 ≤25 m 10.9%。

**结论**：约 36%–46% 的参考边界在 OSM 中没有直接线源；这是纯 OSM
方案的硬上限。边界系统差异首先来自数据，不是 XGB 或后处理。

## 2. 规模结构阶段：核心区严重欠分割

| 指标 | 参考 | 1.4.3 底图 |
| --- | --- | --- |
| 区数 | 1707 | 1510 |
| 面积 p50 | 0.704 km² | 1.418 km² |
| 核心区数量 | 1620（94.9%） | core 类 1275 |
| 核心区面积 p50 | 0.695 km² | 1.468 km² |
| 农村区面积 p50 | 3.746 km² | 9.18 km² |

核心区我们的区面积约是参考的 **2.1 倍**，区数少 345 个。深圳的问题
不是“碎”，而是**核心区该密不密**。

## 3. 面块/分组阶段：两边边界系统互相穿插

对 1.4.3 分区与参考做重叠分析（重叠 ≥10% 面积计）：

- **72.8%** 的我们的区与 ≥2 个参考区重叠，平均每个我们的区跨 **2.38** 个参考区；
- **76.0%** 的参考区被 ≥2 个我们的区切开；
- 每个参考区的最佳 IoU 均值 0.286（核心 0.290，农村 0.159）；
- 0 重叠参考区 11 个（多为海边/边界微网格）。

两边都“多对多”，说明不是简单的粗/细问题，而是**边界网络不对齐**：
我们的边界穿过参考区，参考边界也穿过我们的区；只靠合并/切分区无法
同时解决。

## 4. XGB 合并阶段：对深圳是负收益

服务默认合并 4% 相邻区（62 对）：

- 区数 1510 → 1449，IoU 0.3303 → 0.3311，几乎不变；
- 44 个合并组中，**21 组（47.7%）合并的两个区最佳参考不同**，即跨过了
  参考边界（错误合并）；
- 合并组面积 p50 2.29 km²，进一步放大“大区”；
- 合并后每个我们的区平均跨 **2.42** 个参考区（比合并前 2.38 更差）。

**结论**：对深圳这种区数已少于参考、核心区 p50 只有参考一半的城市，
合并方向是错的。跨城市学到的“局部合并增益”没有识别出
“城市整体处于欠分割状态”这一全局状态。

## 6. 最终残差：还剩什么

成品（2042 区）：

- **66.5%** 的我们的区仍与 ≥2 个参考区重叠，平均每个区跨 **2.12** 个参考区；
- 参考区被切开比例 80.2%（边界网络仍不对齐）；
- 最佳 IoU：整体 0.325，核心 0.330，农村 0.176；
- 面积 KS 0.222，边界 F1@25 0.2286，Chamfer 270.6 m，
  ARI 0.213，归一化 VI 0.304；
- 参考边界仍有 36%–46% 不在 OSM 15 m 内。

**剩余差距分解**：
1. 数据上限：约 4 成参考边界没有 OSM 线源（尤其农村/山地）；
2. 边界系统：即使有 OSM 线，参考选择的线与我们的切分线也不完全一致；
3. 全局粒度：核心区即使切到 p50 0.9 km²，仍比参考 0.695 km² 粗，
   且切分点只落在有 OSM 的地方；
4. 后处理：合并阶段对深圳负收益，必须按城市状态关闭；
5. 模型：跨城市“局部合并增益”没有城市级欠分割特征，无法自行判断
   “这个城市应该多切而不是合并”。

## 7. 可落地的改进

1. **城市级粒度判断**：生成前比较“当前区数/面积 p50”与预算，处于
   欠分割（区数 < 参考预算或 p50 > 1.3×目标）时禁用合并，直接加密；
2. **按类别的加密阈值**：核心区用参考 core p50（深圳 0.695）而
   不是统一最小面积；农村用 p90（17 km²），避免一刀切；
3. **人工线**：剩余 36%–46% 的非 OSM 边界是下一阶段唯一可突破的方向；
   已有的悬空端点连接线/密度脊线分支可作为候选生成器；
4. **评价**：同时看 IoU、匹配率、面积 KS、边界 F1、ARI/VI 和读图，
   避免只优化某个均值。

    --ours aoi_zoning_delivery/cache/agg_units/深圳市-density-1.4.3.geojson \
